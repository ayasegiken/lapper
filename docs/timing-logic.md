# 計測ロジック

`lapper-core` の動作のリファレンス。

## 考え方

- 入力はすべて追記だけのログ（`Event` の並び）として保存し、書き換えない。訂正も新しいイベントとして追記する。
- 「どの通過がどの車の走行か」は、`compute(config, log, now)` でログ全体から毎回計算し直す。
  通過記録が遅れて届いても、報告や訂正が後から来ても、関係する割り当てが自動で直る。
- 同じログからは常に同じ結果になる。通過記録がログに届いた順番は結果に影響しない（時刻で並べ直す）。
- 時刻はすべてコースの時計（計測ボックスの時計）のマイクロ秒（`Micros`）。

## コース

コースは「ゲートの通過順の並び」として定義する。並びの位置をポジションと呼び、0 がスタート、最後がゴール、その間が中間計時。

| 例 | 意味 |
|---|---|
| `[S, I1, I2, G]` | スタート、中間 2 つ、ゴール |
| `[SG, SG]` | スタートとゴールが同じ光電管 |
| `[S, A, B, A, G]` | 同じゲート `A` を 2 回通る |

区間 `i` はポジション `i` から `i + 1` まで。

## 入力（`Event`）

| イベント | 内容 |
|---|---|
| `Passage` | 通過記録（ID、ゲート、打刻時刻、センサー / 手動）。ID はログ全体で一意 |
| `SetVoid` | 通過記録を無効にする / 無効を取り消す（人がゲートを横切った、など） |
| `Enqueue` / `Dequeue` | 出走待ちの列に車を入れる / 外す。`at` の時刻で効く（過去の時刻も指定できる） |
| `SetCar` | 走行の車を指定する（`Car`）、車なしにする（`NoCar`）、指定を取り消す（`Auto`） |
| `ReportOff` | コースアウト / リタイアの報告。最後に通過したポジションと報告の時刻 |
| `CancelReport` | 報告を取り消す |
| `SetPenalty` | パイロンタッチの回数、ミスコース、DNF を設定する（置き換え） |

走行は、その走行を始めたスタートの通過記録の ID（`RunId`）で指す。同じ対象への訂正が複数あれば、ログで後のものが優先される。

## 計算の手順

### 1. 通過記録の前処理

1. 打刻時刻からゲートごとの遅延（`GateConfig::delay`）を引いて、通過時刻とする。
2. `SetVoid` で無効にされた通過を除く。
3. 二重反応を除く: 同じゲートで、受け付けた通過から `lockout` 以内の通過は無視する（`Debounced`）。
   無視された通過を指す訂正は、それを無視させた通過（実際の走行）に付け替える。

### 2. 時刻順の割り当て

残った通過記録と、出走待ちの列の操作を時刻順に処理する（同じ時刻なら列の操作が先）。各時刻の処理の前に、
最大走行時間（`max_run_time`）か最大区間タイム（`max_segment`）を超えた走行を時間切れとして外し、
報告の時刻を過ぎた走行を報告済みとして外す。

通過 1 つの割り当て:

1. 走行中の走行のうち、この通過を受け取れるものを探す。受け取れる条件:
   - 次に通るポジション（中間は飛ばしてよい）のゲートがこの通過のゲートである。
   - 最後の通過からの経過時間が、その間の区間の最小タイム（`min_segment`）の合計以上。
   - 報告があれば、報告のポジションより先ではない。
2. 飛ばすポジションが最も少なく、その中で最も古い走行に割り当てる。飛ばしたポジションは「抜け」（`Missed`）になる。
3. どの走行も受け取れず、スタートのゲートなら、新しい走行を始める。
4. どちらでもなければ、どこにも割り当てない（`Orphan`）。

**矛盾からの付け替え**: 走行 A が次に通るゲートの通過が来たのに、A の最後の通過（中間）から最小区間タイムが
経っていない場合、その中間の通過は後続の走行 B のもので、A はそこで反応が抜けていたと考える。B がその中間の通過を
受け取れて、A がその中間を飛ばしてこの通過を受け取れるなら、中間の通過を B に移し、この通過を A に割り当てる。
両方の走行に `Reassigned` の目印を付ける。A より古い走行がこの通過を受け取れるときは、そちらを優先する。

**新しい走行の車**: `SetCar` の指定があればその車（列にいれば列から外す）。なければ列の先頭の車。列が空なら未割当。
指定された車は列の先頭を消費しないので、途中の走行を 1 つ訂正すれば、それ以降の列からの割り当ては正しくなる。

**押し出し**: 同時走行の上限（`max_on_course`）に達しているときにスタートがあると、走行中の 1 台を外す（推定）。
選ぶのは「進み具合のわりに最も遅れている」走行: 最後の通過からの経過時間を、次の区間のそれまでの区間タイムの中央値で
割った値が最も大きい走行。中央値がまだない区間にいる走行があるときは、最も古い走行。

**報告**: `ReportOff` の走行は、報告のポジションを通過した時点（すでに通過していればその時点）か、報告の時刻の
早い方で外れる。報告のポジションより先と、報告の時刻より後の通過は受け取らない。

### 3. 結果

- `Run`: 車と車の決まり方、ポジションごとの通過、状態、ペナルティ、結果、目印。
- `RunStatus`: `Running` / `Finished` / `Off`（`Reported`、推定の `PushedOut`・`TimedOut`）。
- `RunResult`: `Time`（ペナルティ込み）/ `MissCourse` / `Dnf` / `Running`。
  タイム = ゴール − スタート + パイロンタッチの回数 × `pylon_penalty`。
- `PassageReport`: 通過記録ごとの扱い（`Assigned` / `Debounced` / `Void` / `Orphan`）。
- `Outcome::standings()`: 車ごとのベストタイム。

### 目印（確認を促す）

`Run::needs_review()` は、推定による状態か、次の目印があるときに真。

| 目印 | 意味 |
|---|---|
| `MissingPass` | 通過記録の抜けを飛ばして割り当てた |
| `Reassigned` | 矛盾から割り当てを付け替えた |
| `SlowSegment` | 区間タイムが全走行の中央値の `slow_segment_percent`（既定 150%）を超える |
| `FastSegment` | 区間タイムが全走行の中央値の `fast_segment_percent`（既定 80%）を下回る |
| `NoCar` | 車が決まっていない |

中央値は区間タイムが 3 つ以上あるときだけ使う。

## 設定（`Config`）

| 項目 | 既定値 | 内容 |
|---|---|---|
| `gates` / `default_gate` | 遅延 0、`lockout` 500ms | ゲートごとの遅延と二重反応の無視時間 |
| `min_segment` | 0 | 区間ごとの最小タイム。短すぎる区間タイムになる割り当てをしない |
| `max_segment` | なし | 区間ごとの最大タイム。超えた走行は時間切れ。中間の抜けを考えて余裕を持たせる |
| `max_on_course` | なし | 同時走行の上限 |
| `max_run_time` | なし | 最大走行時間 |
| `pylon_penalty` | 5 秒 | パイロンタッチ 1 回の加算。競技の規則に合わせて設定する |
| `slow_segment_percent` / `fast_segment_percent` | 150 / 80 | 目印の基準 |

`min_segment` は割り当ての精度に大きく効く。最速の車でも下回らない値（標準タイムの 6〜7 割程度）を設定する。
スタートとゴールが同じ光電管のコースでは、次の車のスタートが前の車のゴールと見分けられるよう、
スタートの間隔が `min_segment` より短くなる運用にするか、1 台ずつ走らせる。

## 既知の限界

通過記録と列だけからは見分けられないため、次のケースは誤ることがある。多くは目印で確認を促すが、
目印が付かないこともある。

- **報告のないコースアウト**: 外れた車が後続車の通過を受け取り、後続車が押し出される。
  外れた車の区間タイムは遅く（または速く）なるので、たいていは目印が付く。報告すれば正しく直る。
- **ゴールの反応の抜け**: 後続車のゴールを受け取る。後続車との差が小さいと目印が付かない。
- **スタートとゴールが同じ光電管**: ゴールの反応が抜けたり、スタート直後のコースアウトが報告されなかったりすると、
  次の車のスタートが前の車のゴールとして扱われる。
- **出走待ちの列のずれ**: 列にいない車のスタート、スタートの反応の抜け、スタートでの誤反応が訂正されないと、
  それ以降の走行の車が 1 台ずつずれる。途中の 1 走行を訂正すれば、そこから先は直る。
- **スタートの反応の抜け**: 走行そのものが記録されない。
