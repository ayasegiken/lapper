# 計測ボックスとサーバーのやり取り

計測ボックス（と仮想ボックス `lapper-vbox`）が lapper-server に通過を送るときの形式。型は [`lapper-protocol`](../crates/lapper-protocol) にある。

## 接続

- 今は TCP。サーバーは `--box ADDR` で待ち受ける（例: `--box 0.0.0.0:4000`）。USB シリアルでも、同じメッセージを同じ順で送る。
- 1 行に 1 つの JSON を送り合う（UTF-8、改行で区切る）。`type` でメッセージの種類を表す。
- 接続が切れたら、ボックスがつなぎ直す。

## ボックス → サーバー

| `type` | フィールド | 内容 |
|---|---|---|
| `Hello` | `box_id`、`boot` | 接続したら最初に送る。`box_id` は機器ごとの ID、`boot` は起動ごとに変わる ID |
| `Passage` | `seq`、`input`、`time` | 光電管の通過。`seq` は起動してからの連番（0 から）、`input` は入力端子の番号、`time` はボックスの時計で打刻した時刻（マイクロ秒） |
| `Clock` | `time` | ボックスの時計の今の時刻（マイクロ秒）。通過がなくても 1 秒ごとに送る |

```
{"type":"Hello","box_id":"box-1","boot":"18e7bc14-87d9"}
{"type":"Passage","seq":0,"input":0,"time":1218372}
{"type":"Clock","time":2000104}
```

## サーバー → ボックス

| `type` | フィールド | 内容 |
|---|---|---|
| `Ack` | `seq` | 連番 `seq` の通過を保存した。届き済みの通過をもう一度受け取ったときも返す |

```
{"type":"Ack","seq":0}
```

## 再送

- ボックスは、Ack が届くまで通過を溜めておく。
- つなぎ直したら、`Hello` の後に、Ack のない通過をすべて送り直す。
- つながっている間も、送ってから 2 秒たっても Ack がない通過は送り直す（`lapper-vbox` の場合）。
- サーバーは「`box_id` / `boot`」を送り手、`seq` を番号として重複を除く（[server.md](server.md) の「イベントの追記と再送」）。
  同じ通過を何度受け取っても、ログには 1 回だけ入る。

## サーバーでの扱い

- 通過は、**いちばん新しいセッション**に追記する。ゲートは `input` の番号そのまま（`GateId(input)`）。
  通過記録の ID は、サーバーがセッションの中でまだ使われていない ID を付ける。
- セッションがないときは保存せず、Ack も返さない（ボックスが後で送り直す）。
- `Clock` は、いちばん新しいセッションのコースの時計にする（[server.md](server.md) の「コースの時計」）。
- `Hello` の前に `Passage` が届いたら、接続を切る。読めない行は無視する。

## ボックスの時計

- 時刻は、ボックスの起動からのマイクロ秒。ボックスを起動し直すと 0 から数え直すので、
  セッションの途中でボックスを起動し直すと、時刻が前の通過より前に戻ってしまう。今は新しいセッションを作って使う。
